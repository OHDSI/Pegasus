# Develop a Cohort for a Given Phenotype

Based on the Clinical Definition of a phenotype, develop an operational definition that can be executed against one or more databases in the OMOP Common Data Model (CDM). The implementation uses the Capr R package. The `validateCapr` and `generateCohort` tools compile the Capr definition **server-side**.

Your aim is to achieve greater than 80% PPV and sensitivity as measured by KEEPER in every database.

## Background

Data in observational healthcare databases (insurance claims, electronic health records) are not collected for research purposes. Health outcomes of interest must be inferred using operational definitions combining concept sets (OMOP vocabulary concept IDs for diagnoses, procedures, measurements, drugs, and visit types) with temporal logic.

## Agent Workflow

### Phase 1: Conceptual Design

1. **Review available concept sets:** Examine <available_concept_sets> and their person counts. Concept sets with 0 counts are likely unhelpful. Concept sets with 0 counts are likely unhelpful. Some concept sets are marked as not with descendants; these usually contain a broader concept than the phenotype itself and may be used to capture the disease before a specific subtype is diagnosed.
2. **Apply clinical and database knowledge:** Develop an initial best-guess cohort definition based on clinical reality and your knowledge of EHR and claims data. Outline the required concept sets and temporal logic. Use `getConceptSetsCapr` to fetch Capr `cs(...)` code and per-domain person counts for the pre-created concept sets you need. Use `describeMeasurementValues` to fetch unit concept IDs and corresponding value distributions for measurements.

### Phase 2: Implementation, Generation, and Diagnostics (Unlimited Attempts)

*You may iterate through this phase as many times as needed to obtain reasonable diagnostics before proceeding to KEEPER evaluation.*

Before calling any diagnostic tool, state the expected direction or plausible qualitative range and its rationale without inventing precise epidemiologic benchmarks.

1. **Implementation:** Write the R code using the Capr package to define the cohort (see `<capr_reference>`).
   - **Submission format (required):** Because the isolated server-side sandbox parses a single AST expression and rejects anything outside the documented Capr API, `caprCode` must be a **single `cohort(...)` expression** with every concept set **inlined** as the first argument of its domain query, and **no assignments or helper variables**.
   - Inline each `cs(...)` snippet from `getConceptSetsCapr` exactly as provided.
   - You may call `validateCapr` to verify syntax and API compliance before generating the cohort.
2. **Cohort generation:** Pass the Capr code to `generateCohort` to instantiate the cohort in the database. This returns a **cohort ID**.
3. **Count verification:** Call `getCohortCount` with the cohort ID to inspect overall and per-inclusion-rule counts. Verify that counts and attrition match expectations (e.g., overall count is non-zero and no rule drops an unexpected share of patients).
4. **Incidence rate verification:** Call `computeIncidenceRate` to compute unstratified and age/sex-stratified incidence rates. Verify they align with expectations for the phenotype.
5. **Temporal concept set overlap:** Call `countConceptSetPersonOverlap` against the generated cohort to evaluate concept sets whose inclusion, exclusion, domain, or temporal role remains uncertain, or to assess the impact of adding or removing concept sets when refining an existing definition.

### Phase 3: KEEPER Evaluation (Maximum 3 Attempts)

*To avoid overfitting to the reference set, you are limited to a maximum of 3 total calls to `evaluateCohort`.*

Proceed to KEEPER evaluation only after:
- The generated cohort has a clinically plausible count and attrition profile.
- Important concept-set choices have been examined with temporally aligned overlap windows.
- Stratified and unstratified incidence rates are within expectations.
- Obvious concept-set, domain, and timing issues have been addressed without reference to KEEPER labels.

1. **Evaluate:** Call `evaluateCohort` with the cohort ID to obtain the cohort's operating characteristics against the KEEPER reference set.
2. **Patient profiling:** Call `samplePatientProfile` to inspect individual patient profiles and understand error modes.
3. **Refine or terminate:** Adjust the cohort definition based on evaluation results and return to Phase 2 to regenerate and verify the updated cohort. Stop once `evaluateCohort` has been called three times in total.

## Phenotype Algorithm Design Guidelines

Translate the Clinical Definition into a Capr algorithm grounded in real-world clinical data and sound observational methodology:

* **Model the patient journey:** Trace what happens before, during, and after onset—care settings, diagnostics, procedures, treatments, and resolution—to choose appropriate OMOP domains and temporal windows rather than relying solely on diagnosis codes.
* **Design across EHR and claims:** Claims capture billed diagnoses, procedures, and pharmacy fills well but rarely contain labs; EHRs capture rich clinical measurements but miss out-of-network care and often record drug orders rather than fills. Avoid mandatory lab criteria or single-modality assumptions; use alternative paths (multiple `entry()` queries or `withAny()`) to bridge these gaps.
* **Match logic to the clinical definition:** Place each rule in the right Capr layer (`entry()`, `attrition()`, `exit()`, `era()`). Balance sensitivity and specificity—avoid long AND-chains that drop true cases, while using enough confirmation or care-setting logic to filter out rule-out diagnoses.
* **Capture all phenotype events by default:**
  * **Allow recurrence unless clinically impossible:** Use `primaryCriteriaLimit = "All"`, `expressionLimit = "All"`, a bounded `exit()` strategy (such as `fixedExit()`), and a clinically sensible `era(eraDays = ...)` for acute or recurring conditions. Use `expressionLimit = "First"` only for chronic, irreversible, or explicitly incident phenotypes.
  * **Skip arbitrary prior-observation requirements:** Keep `observationWindow = continuousObservation(0L, 0L)` (do not default to 365 days) unless the phenotype itself strictly requires a washout or lookback.
* **Avoid far-future confirmatory events:** Requiring post-index confirmation far in the future introduces immortal time and selection bias (e.g., if follow-up is lost due to exposure or death). Prefer to restrict post-index confirmation windows to **30 days or fewer**.
* **Account for data longitudinality:** Patients may have years of observation. Do not default to all-time-prior windows (`eventStarts(-Inf, 0)`) for transient or time-varying states (e.g., active drug use, pregnancy, acute infections); use bounded lookbacks and reserve `-Inf` for permanent or lifetime-history criteria.

## Capr Rules

1. **Use only functions and arguments documented in `<capr_reference>`.** If something seems missing, say so—do not improvise API.
2. **Never write a concept ID from memory.** This includes clinical concepts as well as type, unit, status, and provider-specialty IDs.
3. **Construct concept sets only via `getConceptSetsCapr`.** Inline the returned `cs(...)` snippets verbatim.

## Rules & Silent Traps

Most invalid calls throw a validation error; the traps below validate **without error** but produce silently wrong cohorts:

1. **Always make defaults explicit:**
   - Pass `primaryCriteriaLimit` in `entry()`.
   - Pass `attrition` with explicit `expressionLimit` (even with zero rules: `attrition(expressionLimit = "First")`).
   - Pass `exit` explicitly (even `exit = exit(endStrategy = observationExit())`).
2. **Respect Circe's evaluation order when placing index qualifiers:**
   - Execution order: `entry()` queries (with `nestedWith*`) -> `observationWindow` -> `primaryCriteriaLimit` -> `additionalCriteria` -> `qualifiedLimit` -> `attrition()` rules -> `expressionLimit` -> `exit()` -> `era()`.
   - With `primaryCriteriaLimit = "First"`, placing an index-qualifying restriction (e.g., "during an inpatient visit") in `additionalCriteria` or `attrition()` drops patients whose *first* raw event fails it, instead of indexing on their first *qualifying* event. Either set `primaryCriteriaLimit = "All"` (with `qualifiedLimit` or `expressionLimit = "First"` downstream) or attach the qualifier directly to the entry `Query` via attributes or `nestedWith*()`.
   - *Exception:* "First-ever event, and exclude the person if it wasn't inpatient" -> put `firstOccurrence()` on the entry `Query` and the screen in `attrition()`.
3. **Every named `attrition()` rule must be a `Group`** (`withAll()`, `withAny()`, `withAtLeast()`, `withAtMost()`), never a bare `Criteria`. Bare `Criteria` serialize without error and silently disappear.
4. **Incident / new-user cohorts need `firstOccurrence()`** on the entry `Query`. `primaryCriteriaLimit = "First"` alone picks the first event matching the criteria, not the first in patient history.
5. **Start window vs. interval overlap:** `duringInterval(eventStarts(...))` constrains only when the related event *starts*. True overlap with the index date requires both `startWindow` and `endWindow`: `duringInterval(eventStarts(-Inf, 0), endWindow = eventEnds(0, Inf))`.
6. **Recurrent cohorts using `era()` require a bounded `exit()` strategy:** Pairing `era(eraDays = ...)` with `exit(endStrategy = observationExit())` extends the first event through the end of observation, absorbing all subsequent recurrences into a single era. Use `fixedExit(...)` instead.
</silent_traps>

## API Reference

### Top-Level Assembly & Helpers

```r
cohort(entry, attrition = NULL, exit = NULL, era = NULL)

entry(
  ..., # 1+ Queries (OR'd entry paths)
  observationWindow = continuousObservation(0L, 0L),
  primaryCriteriaLimit = c("First", "All", "Last"),
  additionalCriteria = NULL,
  qualifiedLimit = NULL
)
continuousObservation(priorDays = 0L, postDays = 0L)

attrition(
  ..., # named Group args: "Label" = withAll(...)
  expressionLimit = c("First", "All", "Last")
)

exit(endStrategy = observationExit(), censor = NULL)
observationExit()
fixedExit(index = c("startDate", "endDate"), offsetDays)
censoringEvents(...) # 1+ Domain Queries

era(eraDays = 0L)
```

### Domain Query Constructors -> `Query`

Signature: `fn(conceptSet, ...)` where `...` are query attributes. `conceptSet` is **required with no default**—pass `conceptSet = NULL` explicitly if unfiltered. Match constructor to concept set domain.

| Constructor | OMOP Table / Notes |
|---|---|
| `conditionOccurrence`, `drugExposure`, `measurement`, `observation`, `procedure`, `visit`, `deviceExposure`, `specimen`, `doseEra` | Primary domain tables (`visit` -> `VISIT_OCCURRENCE`) |
| `conditionEra`, `drugEra`, `visitDetail` | Prefer `conditionOccurrence` / `drugExposure` / `visit` unless eras or detail are requested |
| `death(conceptSet = NULL, ...)` | `conceptSet` optional |
| `observationPeriod(...)` | No `conceptSet` parameter |

### Criteria, Windows & Logic

```r
# Criteria (absence = exactly(0, ...))
# countColumn required if distinct = TRUE: "DOMAIN_CONCEPT" | "START_DATE" | "VISIT_ID"
exactly(x, query, aperture = duringInterval(eventStarts(-Inf, Inf)), distinct = NA, countColumn = NA_character_)
atLeast(x, query, aperture = duringInterval(eventStarts(-Inf, Inf)), distinct = NA, countColumn = NA_character_)
atMost(x,  query, aperture = duringInterval(eventStarts(-Inf, Inf)), distinct = NA, countColumn = NA_character_)

# EventAperture & EventWindow (negative = before index, 0 = index date, positive = after; -Inf/Inf unbounded)
# restrictVisit = TRUE restricts match to the same visit_occurrence_id as the index event
# ignoreObservationPeriod = TRUE allows matches outside the index observation period
duringInterval(startWindow, endWindow = NULL, restrictVisit = FALSE, ignoreObservationPeriod = FALSE)
eventStarts(a, b, index = c("startDate", "endDate"))
eventEnds(a, b, index = c("startDate", "endDate"))
# Common: (-Inf, 0) on/before; (-Inf, -1) strictly before; (-365, -1) prior 365d excl. index; (0, Inf) on/after

# Groups -> Group (combine Criteria, nested Groups, and demographics)
withAll(...)   withAny(...)   withAtLeast(x, ...)   withAtMost(x, ...)

# Nested / Correlated Criteria -> query attribute (evaluated relative to the query's own event date)
nestedWithAll(...)   nestedWithAny(...)   nestedWithAtLeast(x, ...)   nestedWithAtMost(x, ...)
```

### Comparison Operators

`lt(x)`, `lte(x)`, `gt(x)`, `gte(x)`, `eq(x)`, `bt(x, y)` (between, inclusive), `nbt(x, y)`.
Type follows the input (`18L` integer, `18.0` numeric); `bt`/`nbt` require matching types.

### Query Attributes & Demographics

Pass query attributes via `...` inside a domain query constructor. Demographics work inside both a `Group` (for attrition rules) and a `Query`.

- **Numeric `f(op)`:** `age` (any/Group), `daysOfSupply` (`drugExposure`), `drugRefills` (`drugExposure`), `drugQuantity` (`drugExposure`), `valueAsNumber` (`measurement`/`observation`), `rangeHigh` (`measurement`), `rangeLow` (`measurement`), `rangeHighRatio` (`measurement`: `value_as_number / range_high`), `occurrenceCount` (`conditionEra`/`drugEra`), `eraLength` (`drugEra`), `doseValue` (`doseEra`).
- **Date:** `firstOccurrence()` — first occurrence in patient history.
- **Measurement / Observation values:**
  - `valueAsNumber(op)`
  - `valueAsConceptSet(conceptSet)`
  - `measurementUnit(ids)` — integer IDs **only** (from `describeMeasurementValues`; no `ConceptSet`, no unit strings like `"%"`).
- **Visit:** `providerSpecialtyConcepts(...)` — integer IDs, inside `visit()`.
- **Demographics:** `age(op)`, `male()`, `female()`, `genderConcepts(...)` (integer IDs).

## Example Patterns

These examples demonstrate Capr syntax and are not clinical templates. Placeholders such as `cs(<AMI>)` represent exact `cs(...)` snippets returned by `getConceptSetsCapr` and inlined directly.

### 1. Chronic condition requiring lab values and demographics

```r
cohort(
  entry = entry(
    conditionOccurrence(cs(<T2DM>)),
    observationWindow = continuousObservation(0L, 0L),
    primaryCriteriaLimit = "All"
  ),
  attrition = attrition(
    "Adult males" = withAll(male(), age(gte(18L))),
    "Prior HbA1c < 5.7%" = withAll(
      atLeast(
        1,
        measurement(
          cs(<HbA1c>),
          valueAsNumber(lt(5.7)),
          measurementUnit(<UNIT_ID>) # integer unit ID from describeMeasurementValues
        ),
        duringInterval(eventStarts(-Inf, -1))
      )
    ),
    "No prior T1DM" = withAll(
      exactly(0, conditionOccurrence(cs(<T1DM>)), duringInterval(eventStarts(-Inf, 0)))
    ),
    expressionLimit = "First"
  ),
  exit = exit(endStrategy = observationExit()),
  era = era(eraDays = 0L)
)
```

### 2. Recurrent acute event requiring ER or inpatient visit

```r
cohort(
  entry = entry(
    conditionOccurrence(cs(<AMI>)),
    observationWindow = continuousObservation(0L, 0L),
    primaryCriteriaLimit = "All",
    additionalCriteria = withAll(
      atLeast(
        1,
        visit(cs(<Inpatient or ER>)),
        duringInterval(
          startWindow = eventStarts(-Inf, 0),
          endWindow = eventEnds(0, Inf)
        )
      )
    ),
    qualifiedLimit = "All"
  ),
  attrition = attrition(
    "No qualifying AMI in prior 30 days" = withAll(
      exactly(
        0,
        conditionOccurrence(
          cs(<AMI>),
          nestedWithAll(
            atLeast(
              1,
              visit(cs(<Inpatient or ER>)),
              duringInterval(
                startWindow = eventStarts(-Inf, 0),
                endWindow = eventEnds(0, Inf)
              )
            )
          )
        ),
        duringInterval(eventStarts(-30, -1))
      )
    ),
    expressionLimit = "All"
  ),
  exit = exit(endStrategy = fixedExit(index = "startDate", offsetDays = 1L)),
  era = era(eraDays = 0L)
)
```

### 3. Chronic condition with censoring

```r
cohort(
  entry = entry(
    conditionOccurrence(cs(<MDD>)),
    observationWindow = continuousObservation(0L, 0L),
    primaryCriteriaLimit = "All",
    additionalCriteria = withAny(
      atLeast(
        1,
        conditionOccurrence(cs(<MDD>)),
        duringInterval(eventStarts(7, 30, "startDate"))
      ),
      atLeast(
        1,
        visit(cs(<Inpatient or ER>)),
        duringInterval(eventStarts(-Inf, 0, "startDate"), eventEnds(0, Inf, "startDate"))
      )
    ),
    qualifiedLimit = "First"
  ),
  attrition = attrition(
    "18 or older" = withAll(age(gte(18L))),
    "No prior bipolar" = withAll(
      exactly(0, conditionOccurrence(cs(<Bipolar 1>)), duringInterval(eventStarts(-Inf, 0))),
      exactly(0, conditionOccurrence(cs(<Bipolar 2>)), duringInterval(eventStarts(-Inf, 0)))
    ),
    expressionLimit = "First"
  ),
  exit = exit(
    endStrategy = observationExit(),
    censor = censoringEvents(
      conditionOccurrence(cs(<Bipolar 1>)),
      conditionOccurrence(cs(<Bipolar 2>))
    )
  ),
  era = era(eraDays = 0L)
)
```

### 4. Recurrent event with eras (events within `eraDays` are grouped into an era)

```r
cohort(
  entry = entry(
    conditionOccurrence(cs(<UTI>)),
    observationWindow = continuousObservation(0L, 0L),
    primaryCriteriaLimit = "All"
  ),
  attrition = attrition(
    "Treated with antibiotics" = withAny(
      atLeast(1, drugExposure(cs(<Trimethoprim>)), duringInterval(eventStarts(-Inf, 0, "startDate"), eventEnds(0, Inf, "startDate"))),
      atLeast(1, drugExposure(cs(<Fosfomycin>)), duringInterval(eventStarts(-Inf, 0, "startDate"), eventEnds(0, Inf, "startDate"))),
      atLeast(1, drugExposure(cs(<Amoxicillin>)), duringInterval(eventStarts(-Inf, 0, "startDate"), eventEnds(0, Inf, "startDate"))),
      atLeast(1, drugExposure(cs(<Ciprofloxacin>)), duringInterval(eventStarts(-Inf, 0, "startDate"), eventEnds(0, Inf, "startDate")))
    ),
    expressionLimit = "All"
  ),
  exit = exit(endStrategy = fixedExit(index = "startDate", offsetDays = 1L)),
  era = era(eraDays = 30L)
)
```
